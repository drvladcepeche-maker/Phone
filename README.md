# Анализ телефона 2

Отдельная параллельная установка обновлённого Android-приложения (Kotlin). Старое приложение с идентификатором `com.phoneanalyzer` не заменяется и не удаляется.

- Новый идентификатор: `com.phoneanalyzer.next`
- Имя на телефоне: «Анализ телефона 2»
- Текущая версия: 1.3.0 (versionCode 4)
- APK: `Анализ телефона 2-v1.3.0.apk`

Дальнейшие обновления должны сохранять `applicationId = "com.phoneanalyzer.next"` и использовать один постоянный ключ подписи. Не устанавливайте debug-validation APK как основную версию: он предназначен только для проверки сборки и может быть подписан временным ключом GitHub runner.

## Постоянная подпись

В репозитории GitHub добавьте Actions secrets:

- `PHONE_KEYSTORE_BASE64` — Base64 содержимое PKCS12 keystore;
- `PHONE_KEYSTORE_PASSWORD` — пароль хранилища;
- `PHONE_KEY_ALIAS` — alias ключа;
- `PHONE_KEY_PASSWORD` — пароль ключа.

Не помещайте keystore или пароли в Git. После настройки секретов workflow создаёт подписанный APK `Анализ телефона 2-v1.3.0.apk` в артефакте `Анализ телефона 2-v1.3.0`. Сохраняйте исходный keystore в безопасном месте.

## Серверный мост

Приложение использует закрытый Supabase Edge Function `phone-analyzer` и существующую регистрацию устройства из Termux bridge проекта contacts. Токен устройства хранится в приложении с шифрованием Android Keystore. Передача отчёта выключена по умолчанию и выполняется только после подтверждения. Сервер хранит отчёты в таблице `phone_analyzer_reports` с RLS и закрытым доступом для клиентских ролей.

## Цифровой паспорт устройства

Снимки включают публичные параметры аппаратной платформы и сборки Android, экран, приложения, версии, разрешения, статистику трафика и признаки специальных доступов. Сравнение снимков показывает изменения системы и приложений. IMEI, серийный номер, Android ID, координаты GPS и содержимое личных файлов не собираются. Суточные снимки выполняются только после включения пользователем и сопровождаются системным уведомлением.

## Монитор приватности

Вкладка «Защита» читает системную историю AppOps через Shizuku и показывает зарегистрированные обращения приложений к геолокации, камере, микрофону и поддерживаемым датчикам. События помечаются как фоновые или активные по состоянию процесса, если Android сохранил такую метку. Для чтения журнала требуется установленный и запущенный Shizuku с выданным разрешением. Проверка доступна вручную и в необязательном автоматическом режиме с интервалом не чаще одного раза в 15 минут (фактический запуск Android может отложить). Для автоматического режима владелец включает переключатель в приложении; требуется запущенный Shizuku и разрешение на уведомления. Приложение не скрывает проверку и не получает координаты устройства.

Новые фоновые обращения, замеченные автоматической проверкой, вызывают локальное уведомление; ручная проверка также показывает фоновые обращения за последние сутки, если Android разрешил уведомления. Записи журнала могут быть неполными или очищаться системой; отсутствие события не доказывает отсутствие доступа. Фоновое событие — сигнал для проверки, а не доказательство шпионажа или передачи данных.

## Ограничения фоновой активности

Статистика трафика берётся из системного NetworkStatsManager и отображается по UID приложения. Android не гарантирует стороннему приложению точное разделение всего трафика на фоновый и активный режим; объём трафика сам по себе не доказывает утечку данных и не раскрывает адреса назначения или содержимое соединений. История AppOps зависит от прошивки и того, какие операции системные компоненты регистрируют. Датчики движения могут использоваться без отдельного разрешения и не имеют универсального журнала доступа для сторонних приложений.


## Контроль всплывающих окон

Отдельный наблюдатель специальных возможностей (включается владельцем в системных настройках Android) фиксирует метаданные смены окон и проверяет через Shizuku, имеет ли приложение разрешение SYSTEM_ALERT_WINDOW. События являются кандидатами для проверки, а не гарантированным распознаванием рекламы: Android и прошивки могут не передавать все события наложений. Владелец может точечно запретить приложению AppOp SYSTEM_ALERT_WINDOW или вернуть стандартный режим.

Модуль не читает текст и содержимое окон, не блокирует рекламу внутри приложений, видеорекламу за вознаграждение или бонусные показы в играх. Глобальная DNS-фильтрация и VPN-фильтрация в этой версии не включаются, чтобы не ломать вознаграждаемую рекламу.
